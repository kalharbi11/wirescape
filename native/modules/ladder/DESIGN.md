# Ladder Filter — DSP design

## Algorithm, semantics and provenance

Original four-stage TPT one-pole cascade, using each stage `g=tan(pi*f/fs)`, `a=g/(1+g)`, `y=a*x+(1-a)*z`, `z'=2*y-z`. Resonance maps to a previous-sample negative feedback factor `k=0.85*Resonance`, always strictly below unity. Input to the nonlinear element is `(1+k)*x-k*y4_previous`. Drive=0 bypasses the nonlinear shaper for an exactly linear four-pole cascade. At Drive>0 the input is transformed by `tanh((3*Drive)*input)/(3*Drive)`, with unit small-signal derivative and continuous linear limit as Drive tends to 0. The `(1+k)` feedforward term compensates low-level DC feedback attenuation; nonlinear saturation means large-signal DC gain is not unity. A four-pole causal low-pass cascade has <=1 steady-state gain, shaper slope <=1, and feedback k<1, yielding a small-gain bound for fixed coefficients; rapid coefficient variation was separately stress tested, not mathematically proven for every arbitrary sequence. No nonlinear implicit solve, Newton iterations, oversampling or extra memory are used; feedback is one-sample delayed. This is a ladder-inspired approximation only: no analog transistor/diode model, exact classic ladder frequency response, zero-delay feedback or guaranteed self-oscillation. Drive introduces harmonics and possible aliasing; external expert review is mandatory. Finite input magnitude is numerically bounded at +/-1e6 before processing (well outside ordinary audio), poles flush memory below 1e-20 to avoid subnormals, and there is no hard clipping at the output.

## Work and state contract

All mutable DSP state is private to the created instance. `create` uses nothrow allocation and `destroy` frees it; `prepare` validates and initializes its fixed state. `process`, `reset` and `event` perform no dynamic allocation, locking, I/O or host callbacks. Work is O(frames) with fixed per-sample operations, no unbounded loops or recursion. Every output writes each requested frame, including null/unpatched inputs. Empty spans do not change state. Events are applied at their caller-supplied sample boundary; sample-position values are not used to conceal block-dependent processing.

## Source and limits

No external third-party DSP implementation, presets, device driver, font or runtime dependency was included. The math and test code are original; the only implementation pattern adopted from the kit is its descriptor/callback ABI and existing GPLv3 `LinearRamp` contract. All Linux offline outcomes are reproducible at the verified toolchain, but neither operating-system realtime guarantees nor listening quality follows from offline assertions. Integration tests on Windows and the actual application, including save/load and audio audition, remain necessary; Raspberry Pi has not been tested.
