# Engine telemetry: module pre-implementation audit

**Date:** 2026-11-07 · **Baseline:** `main` `cb5a247` · **Scope:** source review only; no physical device, SDK, protocol or realtime code changes.

**Related:** #350 owns T2 telemetry; #351 fixes the misleading LFO wave tail without inventing phase. See the [source preflight on #350](https://github.com/kalharbi11/wirescape/issues/350#issuecomment-6715095830) for cross-thread/protocol analysis.

## Executive conclusion

**Do not modify individual modules to start #350 Part A.** The host already has the *computed parameter buffer* and routes *every event output*. A generic bounded render-owned telemetry collector should observe those facts once per graph without invasive module modifications.

**Part B should be split:** ADSR and Function Envelope publish real level outputs today; an observer can read them **on the render owner** without touching `module2.h`. The LFO's true phase remains private and needs Keel's decision; deriving it from its sine output is ambiguous. None of this establishes that an arbitrary control/sidecar thread may safely read `Engine::output_sample()` during render.

## Prioritized implementation preparation (Keel choices)

1. **Define `effective` snapshot semantics before writing C++.** In `native/engine2/engine2.cpp` `n.param[j]` already contains the post-modulation, post-taper/clamp **parameter-unit** value given to the module. For per-voice params choose what one display value means (channel 0, max/min or range), with a documented fallback. `FakeEngine` currently sends sparse *deltas* and `Ticker.push()` merges them; a disappeared key on disconnect **never clears a past value**. Either use explicit tombstones and UI reset, or full sparse **snapshot replacement** with FakeEngine/Studio test changes. Test disconnect, zero amount, graph rebuild, panic, no modulation, ID reuse and stopped audio. Confirm a rendering module's state even when its output is not physically patched.
2. **Count actual output events at the routing boundary** (`Engine::Impl::route`), not nearby activity inferred from cable visuals or held-note status. Decide whether counts include successful module emission, downstream acceptance, or engine egress; test rejection and backpressure. `PatchCanvas.bindActivity()` only pulses when activity crosses from below 0.5 to above 0.9, so define decay/reset to re-arm. Distinguish this from **signal**-cable dotted activity, which uses last output sample.
3. **Publish RT-safe fixed-capacity snapshots** with graph/generation tagging. `output_sample()` reads mutable engine buffers and is not legal to call concurrently from sidecar control. Use a C++-data-race-free handoff with release/acquire ownership (a non-atomic plain-payload seqlock alone can still race). Keep bounded work, allocation/locks/JSON off native audio callbacks; serialize on control. New snapshots must reset cleanly across live replan and module removal.
4. **ADSR and Function Envelope B1:** inside render, sample `envelope` signal output across the chosen active polyphony range; publish the maximum for UI's 'loudest live voice' contract. If a source has no processed channels, do **not** substitute zero and falsely imply an observed idle signal. `EnvelopeCurve` distinguishes missing telemetry only by retaining its prior state; test reset and missing-data behavior before rollout. Exact stage and accurate curvature are distinct enhancements.
5. **LFO B2:** first rule on how a module-private phase is exported (internal built-in observer vs intentional additive ABI/SDK contract). A C++ helper in `native/sdk/wirescape_sdk.h` by itself has no generic means to expose private `dsp.phase[16]` through current `ws2_descriptor`/host structs. Align sample phase (0–1) with the output sample's frame reference, transport sync, reset and per-voice convention. At 20 Hz a 30 Hz phase stream aliases, so do not promise full continuous 20 Hz waveform fidelity from 30 Hz snapshots; choose honest display policy.
6. **Worklet cap:** `apps/studio/public/web/ws-processor.js` calls `wsw_telemetry()` once per 12×128-frame render blocks: 31.25 Hz at 48 kHz, 62.5 Hz at 96 kHz. Use elapsed rendered frames/sample rate to cap at ≤30 Hz; profile JSON stringify/parse inside the existing AudioWorklet thread. `native/web/web_engine.cpp` already sends optional `outputs`; update/rule on protocol v0 §7 which says `outputs` is omitted.
7. **Tests and Pi evidence:** null sink protocol test + wasm engine test for real modulated parameter, no-modulation absence, disconnect clear; event output counts and decay; gate- and note-driven envelopes including polyphonic max, release/reset; LFO sync/free-run phase, depth zero, per-voice selection; Studio FakeEngine injected present/absent phase; performance telemetry on/off. Use CI and private `pi5` runner for native work; agents do not open real devices.

## Existing UI surfaces and caveats

- `WavePreview.ts`: phase-driven reference wave; the one-pixel live-output splice was a standalone **T1 bug**, fixed on #351. Live sample may still contribute to the **number readout** only when real phase arrives. Lack of phase continues to show `phase not available`. The trace itself is a *sine schematic*, not a real oscilloscope history; Phase B should not imply an exact waveform recording.
- `EnvelopeCurve.ts`: no tracked stage without observed level; currently caches its last stage/level if a later frame omits the module key.
- `Knob.ts` and `FilterDisplay.ts`: cache live values; when `effective` becomes absent or is explicitly cleared, reset to saved base and remove stale modulation indication. Avoid merging a tombstone into number-only TypeScript types.
- `PatchCanvas.ts`: two different metrics share a visualization context: `eventActivity` for event-port pulses, `outputs` amplitude for dotted signal cables. Keep them distinct.
- `RealEngine.ts` and `WebBridge.ts`: already receive/pass through supported telemetry fields; no need to invent values at the adapter level.

## Decision gate to hand Keel

**Can start once Keel has ruled on**: (a) effective data delta/tombstone vs full-snapshot reset; (b) polyphonic reduction and missing/idle semantics; (c) event counting and decay; (d) generation tagging and race-free RT collector; (e) additive protocol change and protected path; (f) exact LFO phase readout extension. **No module interface or DSP source rewrite is justified in advance from this source audit.**
