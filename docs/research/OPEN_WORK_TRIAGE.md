# Open work triage if Wirescape Studio moves from Qt Quick to HTML

**Research snapshot:** 2026-11-01 UTC; public repository kalharbi11/wirescape, default branch main. **Status:** recommendation only; no existing issue/PR is changed by this report. **Inventory:** 8 open PRs and 30 open issues (38 open records). No HTML sketch was attached to this research request; the proposed WIRESCAPE Studio 01 features were taken from the owner's description, not a verified source file.

## Method, limits and decision rule

Read AGENTS.md first, then docs/PLAN.md's Now section, the current issue and latest available handoff, the task/acceptance file named by each active work item, and narrow relevant source locations. Where a task file exists only in an unmerged PR it was read at that PR's exact head. An issue without a task file is marked as such; its inline acceptance or historical evidence is not invented into a task. Last activity is the GitHub updated_at date in **UTC**, not proof that the head passed tests. Issue rows have no independent head/base; the linked open PR, if any, has its own row. PR diff size is GitHub additions + deletions across changed files; it is a *rework exposure*, not an estimate of engineering hours or of discardable source. Linked issue and PR rows represent the same work and must not be added twice.

**Decision labels for this document:** **KEEP** = Qt-independent engine/DSP/MIDI/build/test/docs/infrastructure work stays on its current track, possibly with a small interface adapter later. **PORT** = retain behavior, requirements, fixtures or design, but re-spec and implement the UI-facing part for HTML. **FINISH-THEN-FREEZE** = a nearly complete Qt fix can make the existing app usable during migration; finish its existing acceptance, merge normally only if gates pass, then stop Qt feature development. **CLOSE** = already implemented on main, superseded, historical-only or no longer worth an implementation branch; close only on planner instruction after checking issue bookkeeping. These are recommendations, **not** GitHub state transitions.

**Non-negotiable carryover:** engine audio callbacks cannot allocate, lock, perform I/O, throw or log; tests and cloud/Pi agents cannot open devices or LAN; module/port/parameter IDs are stable, patch migration is lossless and unknown data is preserved (AGENTS.md:56-61). The internal AppEngine facade is explicitly not a public ABI (native/control/app_engine.h:1-5), exposes a native descriptor accessor (app_engine.h:16-19), and already has separate offline and steady-clock-anchored live render entry points (app_engine.h:25-34). A web view must not turn the render thread into an IPC or UI synchronization thread.

**Measured exposure:** the eight open PRs change 5,889 lines across 101 *PR-file entries* (not 101 distinct files). The two recommended Qt transition merges are #200 (359 lines, eight files) and #192 (496 lines, twelve files), or 855 changed lines / 20 PR-file entries. #204 alone contains 401 lines/10 files against its task's 300/6 budget and has a recorded failing Windows Studio test. #209 is 1,050 lines/15 files of mostly reusable engine work, but is not accepted. The six bundled starter JSON files in #192 should be retained regardless of the Qt selector's fate (docs/tasks/STUDIO_STARTER_PATCH_LIBRARY.md@96cad1c:3-21; native/ui/qml/PatchLibrary.qml@96cad1c:31-45). No hours-saved figures are supportable from repository data.
