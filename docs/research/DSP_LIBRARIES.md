# DSP library allowlist research — Wirescape ABI 2

**Research snapshot:** 2026-11-01. **Status:** proposed policy, **not** planner approval. This is research during the project pause, not a dependency change, test result, or release gate. **Scope:** 13 upstream projects (10 requested families plus 3 additional reverb/filter/oscillator sources). No external libraries were built, benchmarked, or run on the Pi/Daisy during this review. A row saying "no allocation observed in inspected path" is a bounded source audit, not a claim about an entire library.

## 1. Wirescape facts and rule of interpretation

- The app and Essentials are GPL-3.0-only, while the standalone SDK is MIT: [`native/sdk/LICENSE:1-13`](https://github.com/kalharbi11/wirescape/blob/main/native/sdk/LICENSE#L1-L13), [`AGENTS.md`](https://github.com/kalharbi11/wirescape/blob/main/AGENTS.md), and [`docs/SDK_AUTHOR_GUIDE.md:21-34`](https://github.com/kalharbi11/wirescape/blob/main/docs/SDK_AUTHOR_GUIDE.md#L21-L34). Modules **using** the MIT SDK may be independently GPL-licensed; copying GPL/AGPL source **into** the MIT SDK is a different proposition and is not approved.
- `prepare` is quiescent/control-side and uses the declared host allocator; `process`, `reset` and event handling are allocation-, lock-, I/O-, exception-, and log-free: [`docs/SDK_AUTHOR_GUIDE.md:81-101`](https://github.com/kalharbi11/wirescape/blob/main/docs/SDK_AUTHOR_GUIDE.md#L81-L101). Audio/CV is float32, 1–16 polyphonic voice channels; block lengths 1..prepared maximum; sample-accurate event offsets. IDs are immutable and patch load is lossless: [`docs/SDK_AUTHOR_GUIDE.md:36-40`](https://github.com/kalharbi11/wirescape/blob/main/docs/SDK_AUTHOR_GUIDE.md#L36-L40), [`:56-66`](https://github.com/kalharbi11/wirescape/blob/main/docs/SDK_AUTHOR_GUIDE.md#L56-L66).
- Existing house precedents: [`native/modules2/macro_oscillator/DESIGN.md:4-18`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/macro_oscillator/DESIGN.md#L4-L18) pins a *closure* of MIT Plaits and stmlib sources rather than every file in their repositories. Its [`:23-51`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/macro_oscillator/DESIGN.md#L23-L51) documents process-global RNG containment, 16,384 workspace bytes **per voice**, 12-frame render quanta, and per-instance fixed memory; [`:54-118`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/macro_oscillator/DESIGN.md#L54-L118) documents the portability patch closure and oracle. Other conventions: [`chaos_lite/DESIGN.md:4-25`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/chaos_lite/DESIGN.md#L4-L25) (original vs derived, memory and state) and [`ladder/DESIGN.md:1-5`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/ladder/DESIGN.md#L1-L5) (algorithm/precision provenance).
- An upstream repository's SPDX-equivalent top-level licence is **not** necessarily the licence of all its code, bundled samples, dependencies, generated DSP, or commercial licensing route. Use the actual file notices and transitive source closure. "GPL module: yes" below means eligible for a GPL-3.0-only Wirescape Essential **subject to preservation of all component notices and obligations**. "MIT SDK: yes" means a copy could be included in MIT SDK materials; otherwise it can still be used by a separately licensed GPL module. This is engineering/licensing triage, not legal advice.
- **Second-pass correction:** [`docs/SDK_AUTHOR_GUIDE.md:81-91`](https://github.com/kalharbi11/wirescape/blob/main/docs/SDK_AUTHOR_GUIDE.md#L81-L91) permits allocation during `prepare` **only via `s.alloc`**. Merely moving upstream `new`, `malloc` or `std::vector::resize` to a quiescent constructor/`prepare` does **not** meet that rule. Hidden FFT scratch, caches and vector buffers must use fixed/host-provided memory, an audited adapter, or a planner-authorised exception. This distinction narrows the approvals below.
- No source was imported by this PR. **NEON** means an explicit upstream AArch64/NEON code path; "scalar" means no NEON path verified in the inspected source, **not** that the Pi 5 cannot run it or that a compiler cannot autovectorize it. **Daisy** means bare-metal Cortex-M7 viability with all allocations in prepare, not simply "cross-compiles for ARM."

## 2. Tiers proposed for the planner

| Tier | Meaning and module-author authority |
|---|---|
| **Approved** | No new planner Stop **for the named leaf functions, licence and pinned source revision** after module DESIGN proves lifecycle, size/latency, and the realtime matrix below. Additional upstream APIs or a new revision are **not** automatically covered. |
| **Approved-with-notes** | No planner Stop only when the documented restrictions are satisfied in DESIGN (for example, preallocation, generated-code licence closure, pinned legacy code); otherwise escalate. |
| **Needs-planner** | Stop before importing or linking. Material build, licensing, threading, or portability decision remains. |
| **Rejected** | Not part of the ordinary GPL-3.0/MIT-SDK dependency path; a separately authorised exception or alternative implementation is required. |

**Second-pass proposed counts:** **3 approved, 3 approved-with-notes, 6 needs-planner, 1 rejected** = **13 families**. Classification is per named symbol and pinned revision, never an entire upstream library. This tiers *upstream use*, not code-review waivers. All new modules still need usual tests, stable IDs and lossless patch behaviour.

## 4. Actual callback code audit (facts vs required restrictions)

The *functions* below are the specific inspected evidence. "No direct allocation" excludes deeper callees until checked; the builder must close every reachable call graph at its pinned revision, including constructors, lazily initialized statics, logging, virtual dispatch and failure paths.

1. **DaisySP**: [`Source/Synthesis/oscillator.cpp:7-59`](https://github.com/daisyaudio/DaisySP/blob/master/Source/Synthesis/oscillator.cpp#L7-L59) `Oscillator::Process` does arithmetic, phase updates and a waveform switch; there is **no visible allocation, mutex or I/O** in that function. [`oscillator.h:50-113`](https://github.com/daisyaudio/DaisySP/blob/master/Source/Synthesis/oscillator.h#L50-L113) has explicit `Init`/`Reset`. **Restriction:** approve that leaf plus equivalently audited fixed-state filters, not pitch-shifter/reverb or the separate DaisySP-LGPL submodule. A concrete host-allocator-compatible option is DaisySP's [`FIRFILTER_USER_MEMORY` in `Source/Filters/fir.h:29-36,90-115`](https://github.com/daisyaudio/DaisySP/blob/master/Source/Filters/fir.h#L29-L36), which accepts caller-provided state and coefficients.
2. **Mutable Plaits**: [`voice.cc:37-88`](https://github.com/pichenettes/eurorack/blob/master/plaits/dsp/voice.cc#L37-L88) `Voice::Init` iterates the engine registry and reuses a `BufferAllocator`; [`:90-115`](https://github.com/pichenettes/eurorack/blob/master/plaits/dsp/voice.cc#L90-L115) `Voice::Render` begins fixed DSP/sample-state operations. The **Wirescape adapter** already documents thread-local RNG isolation, fixed 16,384-byte workspace/voice, 12-frame FIFO, and no allocation in process/reset [`macro_oscillator/DESIGN.md:23-51`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/macro_oscillator/DESIGN.md#L23-L51). **Restriction:** reuse only this proven closure/portability patch set or re-audit new voice engines, globals and external resources.
3. **Signalsmith**: [`delay.h:43-67`](https://github.com/Signalsmith-Audio/dsp/blob/main/delay.h#L43-L67) `Buffer::resize` and `reset` call `std::vector::assign`; **never call resize in process**. Same-size `reset` normally reuses capacity but violates an absolute "no potentially allocating containers in reset" proof without implementation/test, so use prefilled element loop if necessary. [`delay.h:85-110`](https://github.com/Signalsmith-Audio/dsp/blob/main/delay.h#L85-L110) views read/write existing storage. [`fft.h:148-195`](https://github.com/Signalsmith-Audio/dsp/blob/main/fft.h#L148-L195) `setPlan` uses resize/reserve/push_back: planning belongs only to prepare. **Second-pass restriction:** `Buffer::resize`/constructors and FFT `setPlan` allocate via upstream vectors and do **not** satisfy the `s.alloc`-only setup rule even in quiescence. The greenlisted symbols are [`filters.h:45-50,244-255`](https://github.com/Signalsmith-Audio/dsp/blob/main/filters.h#L45-L50) `BiquadStatic::operator()`/`reset()` with fixed inline state. `BoxFilter::set` can grow storage when length exceeds the maximum ([`envelopes.h:187-209`](https://github.com/Signalsmith-Audio/dsp/blob/main/envelopes.h#L187-L209)); delay/FFT need host-owned adapters or a planner-approved policy exception. No-process-allocation tests alone cannot waive setup provenance.
4. **Faust**: [`architecture/faust/dsp/dsp.h:45-85`](https://github.com/grame-cncm/faust/blob/master-dev/architecture/faust/dsp/dsp.h#L45-L85) defines explicit memory-manager allocate/destroy hooks; [`:92-124`](https://github.com/grame-cncm/faust/blob/master-dev/architecture/faust/dsp/dsp.h#L92-L124) lifecycle `init` and [`:180-204`](https://github.com/grame-cncm/faust/blob/master-dev/architecture/faust/dsp/dsp.h#L180-L204) `compute`. **No universal promise**: inspect generated C++ `compute` and all architecture code for `new`, tables, locks or buffer expansion. ## 6. Realtime no-allocation test pattern (proposed, NOT executed)

**House baseline:** [`native/tests2/allocation_watch.cpp:8-39`](https://github.com/kalharbi11/wirescape/blob/main/native/tests2/allocation_watch.cpp#L8-L39) overrides all ordinary/array, aligned and nothrow global C++ `new` forms, incrementing an atomic counter while enabled; [`allocation_watch.h:5-12`](https://github.com/kalharbi11/wirescape/blob/main/native/tests2/allocation_watch.h#L5-L12) scopes the watch. The existing [`macro_oscillator/tests.cpp:80-89`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/macro_oscillator/tests.cpp#L80-L89) asserts zero around direct ABI2 `process` and [`:213-215`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/macro_oscillator/tests.cpp#L213-L215) checks reset. [`chaos_lite/tests.cpp:135-155`](https://github.com/kalharbi11/wirescape/blob/main/native/modules2/chaos_lite/tests.cpp#L135-L155) additionally warms 256 blocks, then checks **10,000** graph render callbacks, recording median/p95/worst µs. **Limitation:** this counter does **not** intercept direct C `malloc/calloc/realloc` or arbitrary allocator hooks; its global enabled bit is not thread-local; it detects exercised allocations, not the absence of every possible path.

**Recommended extension (future implementation; no files changed here):**

1. Build an **offline ABI2 test** with deterministic host buffers from `s.alloc` and instrumented allocation functions; no devices, LAN or file I/O. Pre-allocate the fixture, parameters, event arrays, scratch and output **before** switching the guard on. `prepare` and object construction are not guarded; `reset` is guarded independently, after warm-up and again after arbitrary valid history.
2. In a dedicated, serial test executable, interpose C++ `new/new[]` (including aligned, sized, nothrow) **and** C `malloc/calloc/realloc` in the compiled closure and third-party allocators. On ELF, use `--wrap` for direct C calls plus symbols as appropriate; on MSVC intercept the linked CRT allocator or supply tracked allocator shims and document any uninstrumented DLL/CRT. Wrap optional system allocators used by the library. Do **not** call a logging/assertion API inside the guard's allocation hook; increment an atomic/`thread_local` counter or set a failure bit, then assert **after** the callback exits. Keep hooks nonallocating and test their own zero/positive control.
3. Guard **only** `descriptor->process(instance,&ctx)`, `reset` and event callback slices, then separately guard `engine.render` to catch host-induced allocation. Watch exception escapes, error/host logging, mutex or condition-variable waits (hook or static inspection), and file/network/device entry points. Baseline must show **zero** operations per invocation, including invalid-but-bounded inputs and allocation-failure simulation during `prepare`.
4. Suggested fixed matrix: sample rates **44,100 / 48,000 / 96,000 Hz**, frames **1 / 17 / 64 / 256**, voices **1 / 2 / 8 / 16**, inputs **CONSTANT / varying**, **64 callbacks per combination** = **3 × 4 × 4 × 2 × 64 = 6,144 guarded callback invocations** per module; also exercise all supported event types and maximum bounded event density. Repeat reset/watch after each operating mode. Where max_block is smaller than 256, choose prepared maximum and record that substitution.
5. Change parameters **inside** the guarded callback for a distinct test (including maximum delay/reverb size, resampler ratio and impulse-response changes) because many libraries allocate only when a setter is triggered. Test first callback, configuration switches, 16 voices, zero/denormal/negative-edge input, block splits **1+17+…** versus a reference contiguous render, error paths, separate instances and concurrent streams. Never let a test-only mutex obscure a library mutex.
6. Use ASan+UBSan on **compiled source including third-party closure**; add CMake compile probes on Windows x64, Linux ARM64 scalar + NEON where available, and separate cross-compile for Cortex-M7 **only when claiming Daisy**. No devices or LAN sockets. For DSP source-size evidence, record link map/code bytes and stack usage on target; do not extrapolate latency from a different CPU.
7. **Pass criteria:** alloc=0 and lock/wait/I/O=0 within every guarded process/reset/event callback, bounded work, zero thrown exceptions, finite outputs, deterministic reset, correct CONSTANT flag, state and ID compatibility, no unintended module-global state, acceptable measured latency and memory. **No test provides a mathematical proof of all future paths**: keep the transitive source audit and fail closed when a code revision, compile option or enabled upstream class changes.

**C++ sketch (conceptual, not a committed implementation):**

```cpp
// Host buffers, objects, schedules and all scratch built before the guard.
// Reprepare for EACH changed rate/block/channel configuration.
for (auto rate : {44100, 48000, 96000})
  for (auto frames : {1, 17, 64, 256})
    for (auto voices : {1, 2, 8, 16})
      for (auto mode : {Constant, Varying}) {
        configure_quiescent(rig, rate, frames, voices, mode);
        prepare_and_warm(rig); // quiescent, uses host s.alloc
        for (int repeat = 0; repeat < 64; ++repeat) {
          set_preallocated_inputs_and_params(rig, repeat);
          uint64_t before = all_allocator_counters();
          {
            NoAllocOrLockGuard scope; // C++ new + direct C/other allocators
            status = rig.descriptor->process(rig.instance, &rig.ctx);
          }
          REQUIRE(status == WS2_OK);
          REQUIRE(all_allocator_counters() == before);
          REQUIRE(outputs_finite_and_flags_valid(rig));
        }
        { NoAllocOrLockGuard scope; rig.descriptor->reset(rig.instance); }
        REQUIRE(no_forbidden_operations());
      }
```

**Instrumentation caution:** `new`/`malloc` shims must not count fixture setup, `REQUIRE`/`printf`, timing vector growth or output comparisons. Avoid overriding dynamic memory in shipping modules. A "zero malloc" result on a library that allocates via a custom arena is not proof that the arena is bounded; record host allocator calls and high-water marks separately.
