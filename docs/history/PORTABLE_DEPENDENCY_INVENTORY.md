# Portable dependency inventory

This packet originally inventoried the Windows package
`build/packages/wirescape-release-20261026T075153Z`. New packages are generated by `python tools/dev.py check --package`; use the `package_directory` in the latest passed package report. Current acceptance also checks normal-window startup with SDK paths removed and writes an automatic SHA integrity report outside the package. It is an experimental local
development package, not an installer or public redistribution release. Its
README says audio starts off and calls out the need for clean-Windows and
physical-audio validation. This inventory does not launch any packaged binary
or load any DLL.

## Reproduce the inventory

From the repository root, run:

```powershell
python tools/foundation/package_inventory.py --package build/packages/wirescape-release-20261026T075153Z --output build/packages/package-inventory.json
```

The report hashes all files under the package except `package-manifest.json`
(which is the manifest itself), compares those paths and SHA-256 values with
the manifest's `files` mapping, lists missing, unexpected and changed files,
and summarizes runtime filenames. It exits 0 for an exact match, 1 for package
drift, and 2 for an unreadable or invalid manifest. If `--output` is omitted,
JSON is printed to standard output. It uses only the Python standard library.

## Remaining deployment gates

- No isolated clean Windows machine result is established here. On a clean
  machine, copy the staged folder to a path outside the checkout, compare its
  inventory report, then launch `wirescape_studio.exe` normally and record the
  Windows version, displayed version, startup result and loaded binary paths.
  Do not interpret a local package hash check as a clean-machine smoke test.
- The earlier Windows Application Control block was cleared when the user turned Smart App Control off. Agents did not alter protection. Current local package startup checks pass; this does not establish public distribution trust or clean-machine compatibility.
- Audio hardware testing remains user initiated. Startup and offline checks
  keep audio off; record physical device tests separately from package checks.
- ARM64 headless build and Raspberry Pi execution have not been verified. A
  recipe or available tool is not evidence of a successful build or hardware
  run. Record the actual compiler/toolchain availability before planning that
  gate; do not install a broad toolchain solely to fill this inventory.
- The package manifest establishes file hashes, not the complete third-party
  source, license and notice set. Review relevant Qt SBOM component records
  and all dependency distribution terms before proposing public release.
