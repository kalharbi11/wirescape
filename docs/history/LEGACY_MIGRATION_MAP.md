# Legacy to Essentials migration map (evidence only)

This is preparation for a later explicit migration implementation. It records local source facts and unresolved choices; it does not define an executable conversion or claim sound-equivalent migration. The native format is `wirescape.native.patch` v1 with numeric module IDs, descriptor parameter IDs, and its own connections (`native/ui/studio_controller.cpp:22-31, 141-160`). The read-only inspector retains original bytes and leaves legacy state fields uninterpreted (`native/document/document_reader.cpp:26-31, 54-83`).

## Document-level decisions

| Concern | Observed legacy behavior | Safe migration decision / unresolved point |
| --- | --- | --- |
| Format dispatch | Browser producer currently emits `wirescape.patch` v3 (`web/index.html:500`). Original visual-study producer emits `wirescape.visual.study` v4 (`design_reference/WIRESCAPE_Studio_Original.html:298`). Local v1 shape is in `tests/test_graph.py:32-42`; v2 sequence shape is in `tests/test_sequencer.py:13-22`; active browser load has versioned branches (`web/index.html:506-520`). Inspector recognizes exactly those four tuples and reports other versions/formats without interpreting schema (`native/document/document_reader.cpp:54-69`). | Dispatch strictly on `(format, version)`. Do not infer a historical producer not present locally. Unsupported/unknown inputs need preservation-only handling. |
| Identity | Legacy module IDs and `module:port` cable endpoints are strings (`wirescape/schema.py:74-80, 92-101`). Native IDs are positive integers and native cable endpoints are split into numeric node IDs and port IDs (`native/ui/studio_controller.cpp:22-31, 149-160`). | A deterministic per-document string-ID to integer-ID map is feasible, but collision/duplicate and reference validation must finish before staging. Mapping preserves relationships, not original textual identity; retain source bytes as recovery data. |
| Coordinates | Legacy modules store pixel-like `x`,`y`; the active loader applies old version-specific x offsets to nearby modules around CHAOS (`web/index.html:506-520`). Native UI also stores finite `x`,`y` positions (`native/ui/studio_controller.cpp:23-26, 150`). | For v3 and visual-study v4, carry coordinates unchanged only after deciding whether legacy canvas scale/origin matches native canvas. For v1/v2, choose either faithfully replay the existing browser adjustment once or keep coordinates untouched; no evidence establishes whether exported coordinates may already include an earlier adjustment. Never apply the browser shift twice. |
| Cable shape | Legacy `{from:"id:port",to:"id:port"}`; native `{fromNode,fromPort,toNode,toPort,kind}` (`native/ui/studio_controller.cpp:27-30`; legacy validation `wirescape/schema.py:92-120`). Legacy ports include audio L/R, block-rate mod, gate/clock, and `notes` events (`wirescape/schema.py:20-45`). Native Essentials exposes audio/control only at the controller boundary (`native/ui/studio_controller.cpp:106-112, 154-160`). | Keep unsupported edges and their endpoints in source document/recovery data. A cable is not mappable merely because node IDs convert; signal domain, direction, cardinality, and semantics must match. Native controller currently allows one cable per input (`native/ui/studio_controller.cpp:164-174`) whereas legacy permits multiple sources (`wirescape/schema.py:57-61`). |
| Unknown data | Browser import recreates only installed UI module types and compatible cables (`web/index.html:524`); unknown modules/fields and rejected cables can therefore be lost on subsequent save. Inspector returns the original bytes even on failure or unsupported format (`native/document/document_reader.h:26-31`; implementation `:26-31, 54-69`). Qt's parsed object may collapse duplicate JSON object keys, as the reader header explicitly notes (`native/document/document_reader.h:26-29`). | Preserve original bytes unchanged as the authoritative fallback whenever an unknown module, field, cable, conflicting field, or unhandled format is present. Do not round-trip through `QJsonObject` and claim byte fidelity for such documents. Unknown-field retention in a future editable migrated document is unresolved. |
| Sequence precedence | Browser loader copies `sequence` when `module_state` is falsy (`web/index.html:523`). Host graph/schema prefer `module_state` whenever the key exists, even if null (`wirescape/graph.py:135`; `wirescape/schema.py:82`). Inspector inventories both independently (`native/document/document_reader.cpp:74-83`), and tests prove differing values and explicit null remain distinct (`native/tests/document_reader_tests.cpp:46-57`). | Preserve both fields. If both are present and unequal, report a conflict and do not choose silently. If only `sequence` exists, translation to `module_state` is allowed only after validating the exact module schema; null/empty/falsy precedence is an explicit unresolved policy choice. |
| Visual monitor | Visual-study v4 producer stored per-module `monitor` (`design_reference/WIRESCAPE_Studio_Original.html:298`). Browser import forcibly clears monitor flags for that format (`web/index.html:524`); graph repeats a format-based guard (`wirescape/graph.py:128, 248`). Native Essentials has no physical input monitor module and the app starts audio off (`native/ui/studio_controller.cpp:327-328`, `native/README.md:13-18`). | Treat old visual monitor as presentation-only. Never turn it into live input routing or start audio. Whether to retain it as inert extension metadata in a native document is unresolved; safest now is source-byte preservation and an explicit diagnostic. |

## Module and parameter mapping evidence

Legacy front-panel controls are stored as unitless 0–100 values and clamped to that range (`wirescape/schema.py:127-137`). This is not a general normalized-to-native conversion rule: native values are declared in module-specific engineering units and ranges, and native save keys are numeric parameter IDs (`native/ui/studio_controller.cpp:106-112, 150-160`).

| Legacy module | Observed controls, ports, and payload | Closest native Essentials, with limits |
| --- | --- | --- |
| `interface` | `OUTPUT LEVEL`, `INPUT GAIN` default 71/36; inputs `inL`,`inR` audio; outputs `extL`,`extR` audio (`wirescape/schema.py:39-43`). Host applies output level `/100`, input gain `2*value/100`, and optionally mixes physical stereo input when monitor is enabled (`wirescape/graph.py:336-338, 424-432`). | No equivalent stereo I/O or physical input module inside the native graph. `essentials.output` is a mono graph sink (`native/modules/output/module.cpp:15-18`); the host has separate live stereo duplication and offline mono policies (`native/include/wirescape/output_policy.h:1-4`). Cannot preserve hardware input gain, monitor routing, or exact output scaling. Do not replace automatically with a mono output sink. |
| `modulator` | Controls `RATE`,`SHAPE`,`DEPTH`,`DRIFT`,`RANDOM`, defaults 44/53/67/29/34, each 0–100; input `clock`/`reset`/`rate`; outputs `modA`,`modB`,`gate`; modes LFO/RANDOM/ENVELOPE (`wirescape/schema.py:33-37`). | No native LFO/random/control generator in Essentials. `essentials.adsr` has one envelope output, one monophonic event owner, parameters attack/decay/release in seconds and sustain 0–1 (`native/modules/adsr/module.cpp:28-46, 87-108`); it cannot reproduce 3 modes, two modulation outputs, rate/depth/drift/random behavior, reset/clock semantics. No automatic substitute. |
| `sequencer` | Plugin controls RUN/BPM/SWING/DEPTH/DECAY (defaults 100/50/0/100/35), `sequence` in v2 and `module_state` in v3; inputs clock/reset; outputs typed notes/gate/trig/mod/env (`modules/sequencer/plugin.py:7-14`, `modules/sequencer/engine.py:31-35, 195-204`). BPM maps 40–240; swing up to 0.49 alternating step timing; CV/depth and envelope formulas are implemented in engine (`modules/sequencer/engine.py:195-202, 225-250`). | No native sequencer. Native ABI has note/gate event types but no installed scheduler/state module; current native module set is VCO, ADSR, VCA, mixer, output (`native/modules/*/module.json`). Chord/polyphonic note events, timing, reset, clock, multiple CV lanes, modulation state, and plugin-specific pattern cannot be carried by the current Essentials graph. Preserve pattern opaque; do not coerce it into ADSR/VCO state. |
| `chaos` | Two independent Surge engines; stereo `left`/`right`, mod output, pitch/morph/chaos/cutoff, gate/notes/audio inputs; controls include 30 front controls, two voice envelopes plus `mode`, `advanced`, and raw per-voice overrides (`wirescape/schema.py:20-31`, `wirescape/mapping.py:1-39`, `wirescape/graph.py:372-430`). Controls are 0–100, but macro conversion is nonlinear and mode-dependent (`wirescape/mapping.py:41-95`); raw Surge keys/voice overrides are separate (`wirescape/graph.py:169-179, 262-277`). | No native CHAOS or Surge processor. `essentials.vco` is a mono sine with frequency in Hz and a note-on-to-frequency mapping (`native/modules/vco/module.cpp:20-30, 39-54`); it is not a synth-state mapping. ADSR/VCA can build a simple monophonic oscillator voice, but cannot retain CHAOS tone, stereo, polyphony, macro interactions, mode, modulation, or Surge raw state. Preserve all original values/state as opaque source data; no lossy proxy conversion. |

Other mismatches to carry into implementation: legacy graph permits multiple cables to one input and audio is mono-per-port with stereo represented by L/R pairs (`wirescape/schema.py:3-5, 57-61`); native controller currently limits one edge per input (`native/ui/studio_controller.cpp:164-174`). Legacy note-event and clock ports have no native Essentials counterpart, and native's general declared control/audio ports do not encode legacy gate/clock/notes kinds (`native/ui/studio_controller.cpp:106-112`). Native output selection is a separate `outputNode` field (`native/ui/studio_controller.cpp:22-31`); legacy patches have no equivalent field.

## Preservation-first fallback and next small step

Until a full mapping is approved, unsupported or not-lossless documents should remain byte-preserved and unopened as executable native graphs. A later importer may stage a new native document only when every module, parameter, coordinate adjustment, cable kind, and output selection has an explicit mapping; show a report for skipped/unmapped data and leave the original file intact. For known-but-unmapped legacy documents, expose an inspection/recovery path that retains the source file and diagnostic rather than silently generating a partial native patch. This fallback is a proposal, not a claim that the GUI importer already implements it.

The next small implementation option is a pure mapping planner that returns either `fully mappable` plus a staged native document, or `preserve only` plus structured per-module/field/cable reasons. Based on this inventory, every legacy module kind above is preserve-only with the current Essentials set; no positive module mapping is evidenced. Start by testing the planner's preserve-only decisions and blocker report on the synthetic fixtures. Add a success mapping only after a one-to-one processor/parameter/port contract is established. The planner must not instantiate processors, mutate the live graph, start audio, rewrite the input file, or change the native ABI.
