## Overall assessment

This is a useful, small native feasibility checkpoint. Keep the standalone Qt Quick direction, independent headless C++ engine, separate Essentials module folders, prepared routing/storage, stable port identities, timestamp/generation model, explicit audio start, and script-based development workflow. There is no evidence here requiring a new architecture or language decision.

It is not yet a stable SDK or production instrument. The next work should harden document behavior, parameter feedback, and device lifecycle before adding substantial instruments. The mixer is a suitable independent module and appears compatible on source inspection. Its local integration/testing remains a separate authorized implementation task.

The legacy Python/browser source remains unchanged relative to the baseline tag. New foundation code, tooling, documentation, and handoff files are the relevant committed changes. The user's incoming mixer remains outside `native/modules/`.

## Priority fixes for the next implementation stage

### R01 — P1: protect unsaved work and make patch loading transactional

**Evidence:** `native/ui/studio_controller.cpp:234` loads JSON and performs shallow top-level checks, then at `:243` replaces `document_` and clears `dirty_` before `compileDocument()` establishes whether the candidate is usable. `resetPatch()` at `:225` also replaces the current document unconditionally. The QML New/Open actions and window closing have no dirty-document save/discard/cancel flow.

**Impact:** opening a native-v1 file with invalid graph/parameter data can replace a good edited patch with a failed patch and clear the unsaved indication. New/Open/Close can lose unsaved changes. Missing modules are a different case: deliberately opening a losslessly preserved placeholder document should remain possible.

**Requested edit:** validate the document's syntax/schema separately from processor availability, stage the candidate, and commit only after the appropriate validation succeeds. Add save/discard/cancel handling for destructive document replacement/close. Preserve the current accepted document on malformed input. Keep unknown fields and unavailable-module payloads intact.

**Acceptance:** edit a patch, try New/Open/Close, and cancel each; existing values/positions/cables remain. Reject wrong field types, bad IDs/endpoints, bad parameter values, and unsupported versions without losing the old patch. A valid document with an unavailable module can open/save losslessly with execution disabled. Test successful and failed atomic save.

### R02 — P1: separate editable document state from an executable graph

**Evidence:** `commitTopology()` (`native/ui/studio_controller.cpp:152`) rejects an edit whenever `makeEngine()` cannot prepare an output. Removal (`:184`) routes through it. `makeEngine()` requires an output at `:128` and rejects every unavailable module at `:118`.

**Impact:** the user cannot remove the last Output to rearrange a patch or create a deliberately incomplete patch. Edits to a document containing missing modules can also be blocked even when they would help recover it. These are editing-state limitations, not unsafe audio graphs that should be executed.

**Requested edit:** let a structurally valid document exist in an incomplete/non-executable state. Show a useful readiness diagnostic and disable audio until compilation succeeds. Preserve stopped-stream topology editing for this checkpoint; do not implement live graph swaps to solve this.

**Acceptance:** remove the only Output, save, reload, add a replacement, reconnect, and regain readiness. Preserve disconnected nodes/cables where valid. Keep rejected type-invalid connections out of the accepted graph. Add explicit output selection if more than one output destination is supported.

### R03 — P1: keep displayed parameter values synchronized without resetting delegates

**Evidence:** `setParameter()` updates JSON and emits only `statusChanged()` (`native/ui/studio_controller.cpp:160`). `ParameterControl.qml` displays `descriptor.display` whenever the slider is not pressed, and its `onMoved` ignores the return value of `studio.setParameter()`.

**Impact:** after dragging Frequency from 220 Hz to another value, the displayed label returns to the old descriptor value on release, although the document/engine accepted the new value. A rejected change can also leave the thumb showing a value that was not accepted. The previous decision to avoid rebuilding all delegates during a drag is sound; the missing piece is targeted accepted-state feedback.

**Requested edit:** expose targeted parameter change/acceptance notifications or stable models with per-parameter role updates. Update labels and accepted values, and restore the visual state on rejection. Avoid emitting a full model reset for each mouse move. Handle fixed-range descriptors without division by zero in normalization.

**Acceptance:** mouse and keyboard changes display the accepted value after release; save/reload preserves it. Force queue rejection and verify the UI returns to accepted state. Drag remains uninterrupted. Add a real QML control interaction test rather than calling the controller directly.

### R04 — P1 before live-audio validation: complete the device lifecycle/error state

**Evidence:** `AudioDevice::stop()` (`native/ui/audio_device.cpp:80`) ignores results from stop/close and clears its pointers. Start failure cleanup also ignores close results (`:72`). `running()` in `audio_device.h:17` tests pointer presence, with no stream-active/finished-state path. The callback reports output underflows and processing faults but not unexpected stream termination.

**Impact:** the UI can present a stale running/stopped state after backend failure, and cleanup errors are invisible. Stream quiescence must be established before resetting or destroying the referenced engine. Source inspection does not establish that a live use-after-free occurs; it establishes that the failure path is not checked or tested.

**Requested edit:** define device states and failure/close ownership explicitly, surface errors, and verify that callbacks have ceased before releasing engine resources. Add a mockable PortAudio interface so failures are testable without speakers/hardware. Keep callback work free of Qt/Python calls and blocking operations.

**Acceptance:** simulate open/start/stop/close failure, unexpected backend stop, invalid device and callback fault. No stale UI status, callback after engine disposal, resource leak, or automatic restart/playback. Actual hardware testing remains a separate user-initiated stage.

## Other concrete follow-up items

### R05 — P2: strengthen tests at the UI/document boundary

`StudioController::smokeCheck()` (`native/ui/studio_controller.cpp:262`) changes a parameter by directly calling C++, renders a separate offline engine, and counts four modules/three cables. `native/ui/main.cpp` captures a screenshot and checks model count properties. This is useful smoke coverage, but does not test slider feedback, mouse cable editing, save/reload, dirty-state handling, missing-module recovery, or actual pixel/readability correctness. A model can contain four items even if one is outside the viewport.

Preserve the smoke test and add focused controller/QML tests for R01–R03. Keep smoke expectations independent of the installed palette count so adding the mixer does not invalidate assumptions. Four nodes are correct for the default test patch; five installed module types are a different quantity.

The native suite's roughly 10,000 checks include repeated concurrency-loop assertions; that is not 10,000 distinct test cases. The instrumented no-allocation test observes ordinary C++ `new/new[]` in the statically compiled measured engine/module path. It does not intercept all `malloc`, aligned allocation, native-library or dynamic third-party DLL allocations. Retain the existing narrow claim and expand instrumentation only when a real workload needs it.

### R06 — P2: put finite deadlines on automated checks

`tools/foundation/helpers.py:144` runs build/test/UI commands without a timeout. `native/tests/engine_tests.cpp:240` has producer/consumer retry loops without a watchdog; a consumer regression can hang the test. A failed assertion while the producer is still joinable can also terminate rather than produce the intended caught test failure.

Add per-action subprocess timeouts, a CTest timeout, and bounded concurrency-test shutdown/join. A timeout must be recorded as a failure with the log, not a pass/skipped result. Do not rerun indefinitely or weaken an assertion to clear the milestone.

### R07 — P2: fix reporting provenance and recursive summaries

- `_base_record()` (`tools/dev.py:24`) records HEAD but not whether source was dirty, which sources/binaries were built, or relevant build flags. Stored first-checkpoint reports correctly contain the then-parent baseline hash, but that hash alone does not identify the new uncommitted engine that was measured. Record source cleanliness/fingerprint and actual build configuration.
- `_latest_reports()` (`:220`) includes earlier `report` actions; `command_report()` embeds their `latest_actions` again. Repeated reports can recursively accumulate old summaries. Exclude summary records from summary inputs and summarize the latest relevant result per action/source checkpoint.
- Build records set `ui_enabled` from the requested flag (`:157`), while `native/ui/CMakeLists.txt` quietly skips the UI target if Qt is missing. Distinguish requested UI from an actually produced app target.
- `_qt_prefix()` (`:115`) silently falls back to auto-detected Qt even when an explicit invalid prefix was supplied. An explicit override should fail clearly. Runtime launch should use the SDK selected for the actual build, not independently pick a possibly different installed version.

Use mocked/temp-directory tests for these paths; no heavy build matrix is needed to verify report selection.

### R08 — P2 before controller/device expansion: define musical and overload semantics

- The ADSR is intentionally monophonic and remembers one source/note; it is not a polyphonic/held-note manager. Specify last-note/retrigger behavior when keys overlap and when manual gate and keyboard input interact.
- VCO note-on replaces its internal frequency, while the saved Frequency knob remains the base value. Clarify the base-pitch versus played-pitch model, and avoid misleading effective-value readouts.
- VCA/frequency parameter events currently apply abrupt changes. Add explicitly defined smoothing where needed for click-free performance, with sample-rate/partition tests; do not smooth gates or time-critical events indiscriminately.
- `StudioController::send()` (`:202`) reports every enqueue failure as queue capacity and panics, although invalid/state errors are separate engine results. Distinguish errors and preserve/reconcile accepted control state.
- `ws_engine_render()` (`native/src/engine.cpp:363`) snapshots queue head, so concurrent producers cannot extend that callback's drain forever. That is good. Worst-case event subdivisions still re-run the whole graph and need an explicit work/subdivision budget before accepting dense sequencer/sensor traffic. Current small steady-tone benchmarks do not exercise that frontier.

These are bounded contract extensions and tests, not reasons to restart the engine design.

### R09 — P2/P3: finish ordinary application behavior and deployment

- `refreshDevices()` exists in the controller, but the QML has no action invoking it. Initially only the system-default entry is visible; users should be able to discover/select an output without starting that default stream first.
- Render writes a fixed four-second mono WAV and can cut off long releases. Live/GUI render uses fixed 0.2 output scaling; CLI demo uses a different level. Label the test-render behavior and define one explicit output-level policy before making matched comparisons.
- Successful file rendering is currently sent through `errorText`, so it displays as an error. Separate transient success notices from errors.
- The development app depends on a local Qt SDK and a PortAudio DLL manually copied into ignored build output. Add reproducible packaging/runtime dependency handling and a clean-environment launch check. Do not claim an installer or Pi deployment has been delivered.
- Registry descriptors are loaded from matching DLLs, not validated manifests/trust records. Manifest-governed discovery, explicit enablement, missing-module diagnostics and disable/update lifecycle are still planned SDK work. Keep those boundaries explicit; do not add a marketplace/dependency solver now.
- Consider making idle telemetry event-driven/lower-rate after measuring idle CPU. No idle CPU improvement has been established by this review.
