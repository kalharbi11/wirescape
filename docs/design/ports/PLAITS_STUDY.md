## 3. Proposed Wirescape ABI 2 mapping

**Proposal (not a frozen contract):** module ID `ports.macro_oscillator`; displayed as **Macro Oscillator**; two distinct mono audio signal ports `main` and `aux`, each with 1–16 *voice channels* (not a stereo pair). This follows [Wirescape ABI2 D2–D4](https://github.com/kalharbi11/wirescape/blob/main/docs/specs/ABI2_PLAN.md) and upstream [two-output frame definition](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L164-L167). Set `WS2_AUDIO` and never mark continuously running oscillator output CONSTANT.

**Proposed parameter IDs** (plain-unit linear taper, stable strings, host modulatable/per-voice/automatable except stepped model):

| ID | Range / default | Semantics |
|---|---|---|
| `model` | integers 0…23 / 0; **STEPPED**, no smoothing | Engine selector; preserve existing hysteretic engine-CV choice if provided ([`voice.cc:121–138`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L121-L138)) |
| `coarse` | −48…+48 / 0 semitones | Add to C4-relative pitch, not to host-normalized 1/oct cable ([`voice.h:125–137`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L125-L137)) |
| `harmonics`, `timbre`, `morph` | each 0…1 / 0.5 | Upstream normalized patch settings ([`voice.h:125–130`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L125-L130)) |
| `fm_amount`, `timbre_amount`, `morph_amount` | each −1…+1 / 0 | Upstream `frequency_modulation_amount`, `timbre_modulation_amount`, `morph_modulation_amount` ([`voice.h:130–133`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L130-L133)); negative amounts preserve attenuation polarity |
| `decay`, `lpg_colour` | each 0…1 / 0.5 | Upstream normalized envelope and low-pass-gate colour ([`voice.h:134–137`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L134-L137)) |

**Proposed signal inputs** (never conflate Wirescape signal scaling with hardware volts):

| Port ID (hint) | Proposed mapping |
|---|---|
| `pitch` (`WS2_PITCH`) | 1.0 per octave, 0 = C4; upstream semitone offset = `12 * pitch` plus `coarse`; upstream note baseline C4/MIDI 60 (compare [VCV `Plaits.cpp:184–205`](https://github.com/VCVRack/AudibleInstruments/blob/a1cd335ec6ac44e8be55891854015bf0763f8552/src/Plaits.cpp#L184-L205)). |
| `model_cv` (`WS2_CV_BI`), `fm` (`WS2_CV_BI`) | Feed upstream `Modulations.engine` and `.frequency`; calibrate the mapping by direct equivalence (VCV uses `/5` and `*6` for its voltages: [`Plaits.cpp:203–206`](https://github.com/VCVRack/AudibleInstruments/blob/a1cd335ec6ac44e8be55891854015bf0763f8552/src/Plaits.cpp#L203-L206)). |
| `harmonics_cv`, `timbre_cv`, `morph_cv` (`WS2_CV_BI`) | Preserve upstream dedicated modulation fields and *connected* flags where present; do not substitute host parameter modulation for patch-dependent internal envelope semantics ([`voice.h:139–154`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L139-L154); [`voice.cc:164–225`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L164-L225)). |
| `trigger` (`WS2_GATE`), `level` (`WS2_CV_UNI`) | Map gate high/low and level/velocity; explicitly preserve **connected vs unconnected** status; the firmware uses separate trigger/level patched flags ([`voice.cc:97–119,148–165`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L97-L165)). |
| `notes` (`WS2_EVENT`, note events) | **Optional adapter feature**, map per-channel note-on/off to pitch/trigger/velocity. When a physical/signal trigger is connected, give it precedence; otherwise make event-trigger behaviour deterministic. **To verify:** buffer/event offset-to-12-frame control timing and note ID handling without altering Plaits DSP. |

**Adapter approach:** keep one `plaits::Voice`, one 16,384-byte workspace and a bounded 12-frame staging FIFO **per prepared voice channel**. Use `Setup::alloc` only during `prepare`, declare `memory_requirements` (workspace 16,384 × max_channels as the initial conservative reservation, in **LARGE**, plus aligned staging/FIFO and hot state in **FAST**). Sixteen workspaces reserve **262,144 bytes (256 KiB)** before `sizeof(Voice) × 16`, outputs, and conversion buffers; calculate and report true total after compiling. Upstream workspace size and reuse: [`plaits.cc:54–56,142–146`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/plaits.cc#L54-L56) and [`voice.cc:67–71`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L67-L71). Keep state per channel; never allocate or load hardware resources in `process`.

**To verify:** whether `ws::Setup::alloc` alignment/hint works for the selected transitive DSP, a wrapper-supported failure path when an allocator returns null, per-channel reset semantics, fully lossless patch parameter mapping, and whether `model_cv` needs to be a signal port for upstream latching rather than a host-modulated stepped parameter. State snapshots must be versioned, validate before mutation, and avoid copying raw C++ object pointers into a file.

## 4. Sample-rate choice

| Option | Quality/equivalence | Cost, latency, portability | Decision |
|---|---|---|---|
| **A. Only 48,000 Hz; `prepare` rejects 44,100 and 96,000** | At 48 kHz and identical 12-frame control updates, preserves upstream math and allows a direct integer-output reference; the `kCorrectedSampleRate` constant remains as written ([`dsp.h:36–51`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/dsp.h#L36-L51)). | Cheapest, smallest Daisy path, no resampler/extra latency; Wirescape must report unsupported rate rather than silently render wrong pitch. | **Recommended for first spike.** |
| **B. Always render Plaits internally at 48 kHz, resample to/from host rate** | Preserves upstream internal DSP at its designed rate; output conversion adds bandwidth/ringing/latency and can break bit-for-bit *host-output* equivalence. | Extra CPU, per-channel state, bounded ring buffering and an explicit latency report; 44.1/96 kHz support becomes feasible. Daisy at native 48 kHz can bypass converter. | Candidate later, after profiling and quality tests. |
| **C. Compile 44.1/48/96 kHz source variants** | Not a literal unchanged-DSP port because sample-rate constants and frequency/scaler assumptions are embedded ([`dsp.h:36–51`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/dsp.h#L36-L51), [`voice.cc:155–158,233–243`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L155-L158)). | Multiple variants/validation matrices, likely more code/ROM and risk of changes outside a single constant; complicates Daisy. | Do not take for first port. |

**Recommendation:** start with A, log 44.1/96 kHz as explicitly unsupported. Reserve an internal 12-sample FIFO to handle arbitrary Wirescape host block lengths, including 1, 17 and other nonmultiples of 12. Report any buffering latency; test continuous-frame equivalence across host block boundaries. If demand justifies B, use a bounded, prepared, deterministic resampler and benchmark at 44.1/96 separately. Prior-art resampling is documented in section 7.

## 5. SDK/ABI gaps and required decisions

| Risk / question | Present finding and next verification |
|---|---|
| **12 vs arbitrary host block lengths** | Wirescape requires any frames 1…max ([ABI2 section 6](https://github.com/kalharbi11/wirescape/blob/main/docs/specs/ABI2_PLAN.md)); Plaits declares 12 ([`dsp.h:50–51`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/dsp.h#L50-L51)). | **Trigger timing and note events** | Upstream trigger edges are detected only at `Render` calls, with a short delay and hysteresis ([`voice.cc:97–119,143–153`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L97-L153)). To verify sample-exact event-to-upstream-block semantics; document quantization and do not claim sample-exact triggering if it cannot be preserved. |
| **State save/load** | Upstream public `Voice` exposes init/render, not serialization ([`voice.h:159–181`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L159-L181)); state is buried in engine objects ([`voice.h:205–251`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L205-L251)). | **User data / flash / real-time safety** | `Voice::Render` may call `UserData::ptr` on engine change ([`voice.cc:128–135`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.cc#L128-L135)); firmware version assumes mapped flash ([`user_data.h:57–89`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/user_data.h#L57-L89)). **To verify:** use upstream's hardware-free/test path for factory presets and preloaded immutable buffers, not in-process I/O or flash access. |
| **16 voices and portable memory** | Firmware's 16 KiB arena ([`plaits.cc:54–56`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/plaits.cc#L54-L56) and VCV's 16 arenas [`Plaits.cpp:47–88`](https://github.com/VCVRack/AudibleInstruments/blob/a1cd335ec6ac44e8be55891854015bf0763f8552/src/Plaits.cpp#L47-L88)) imply ≥256 KiB reserved workspace for 16 voices, plus C++ Voice objects. **To verify:** actual `sizeof(Voice)`, arena peak, Daisy FAST/LARGE/SDRAM feasibility, and `prepare` refusal at insufficient memory. | **Randomness and determinism** | Some upstream engines may use their own RNG/state; engine objects are owned per `Voice` ([`voice.h:205–251`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L205-L251)). **To verify:** complete source review for static/global PRNG and reset determinism, matching Wirescape seed rules; no DSP rewrite in the first spike. |
| **Numeric safety and per-rate accuracy** | Output passes upstream limiter/16-bit clip path ([`voice.h:87–114`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/dsp/voice.h#L87-L114)); Wirescape still requires finite outputs and rejects invalid setup. Test NaN/Inf extremes and no mutable global state; do not weaken ABI checks. |
| **Resource inclusion and licence closure** | Transitive DSP dependencies need a compile-time closure audit, not a whole-firmware vendoring shortcut ([`plaits/makefile:38–55`](https://github.com/pichenettes/eurorack/blob/f4cfa7697095a28d292bff758beb51deb49b5a86/plaits/makefile#L38-L55)); exclude STM32 hardware files and `stmlib` exceptions as in section 1. |

The suspected gaps are primarily **adapter feasibility and upstream semantics**, not proof that `module2.h` needs changes. Any real ABI limitation must be raised separately before altering protected headers.

## 6. Tests and evidence required for a future code spike

**No tests were executed for this docs-only study.** The phase B test plan (Track X “Rules for every port”, **item 9**, and the digital-DSP-only eligibility rule, item 6):

1. **Direct upstream reference:** build exact pinned `plaits::Voice` directly inside a headless CTest reference binary; use identical 48 kHz, 12-frame control inputs, seeds, engine selection/level/trigger patched flags and both 16-bit streams. Compare adapter float outputs after documented normalization to the reference *bit-for-bit* where processing order matches, plus sequential output across Wirescape frame divisions (1, 12, 17, max).

## 7. Prior art: VCV Rack Audible Instruments

## 8. Effort, risks and smallest acceptable spike

**Estimate (not a promise):** an unchanged-DSP wrapper/reference-test integration would add roughly **6–12 Wirescape-owned text files** and **500–1,200 lines** (adapter/metadata/CMake wiring, reference CTest, source pin and documentation), excluding fetched upstream source and generated files. A hardened 24-engine, polyphonic, multi-rate version would be substantially larger; likely **weeks**, not a one-day port. **To verify:** translation-unit closure and actual dependency size before giving a stronger estimate.

**Risk order:** (1) flash/user-data path inside engine changes; (2) bit-exact timing through arbitrary blocks and event mapping; (3) actual `Voice` storage/large arena ×16 on Pi/Daisy; (4) deterministic reset, state snapshots and RNG; (5) transitive licence/ARM64 compile closure; (6) later 44.1/96 resampling latency and quality. Upstream evidence is linked in sections 1–7.

**Minimal first spike proposal (separate issue after review/M2 constraints):** use pinned CMake FetchContent with the exact SHAs, no vendoring or upstream DSP edits; register `ports.macro_oscillator`; **48 kHz only, one voice, 12-frame source quantum, models 8 and 10 exercised** while leaving source `Voice` intact; default factory sounds, main/aux, pitch/harmonics/timbre/morph, trigger, level and reset; tests directly against the same upstream sources with no audio device. Then expand to 1/4/16 channels and the full mandatory test/rate/target matrix before code review. If mid-note state round-trip or deterministic reset is impossible without changing DSP, **stop and report** rather than weaken the requirement.

**Open verification list for the compiling agent:** exact pinned transitive source list and per-file licences; size/alignment/peak allocation of each `Voice`; hardware-free UserData behaviour; seeded RNG/global-state audit; precise trigger/event latency; state serialization feasibility; all-target compilation and Pi CPU budget. The study itself does **not** attest to those results.
